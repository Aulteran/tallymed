# TallyMed repository instructions

This repository holds code and code-facing documentation only. Project status, vision, decisions, milestone plans, progress and handoffs live in the [TallyMed project in Notion](https://app.notion.com/p/41eab8277cf7812593a2cd3f3038a951) (workspace AI Headquarters), which is the source of truth. Read it before starting work, and read the specifications in `docs/` that the task links.

- Use Node 24 and the npm lockfile. Run `npm ci`, `npm run typecheck`, `npm test`, `npm run build` and `npm run test:export`. Run the relevant integration and deployment checks for the change. Report unverified checks explicitly.
- Use fabricated household data only. Never connect development threads to real records, backups or live MCP. Preserve auditability, exact money arithmetic and access boundaries.
- Keep public marketing content independent of internal plans. Roadmap entries use descriptive names. Mark previews fictional and describe unreleased capabilities as planned.
- Architecture and rules: see `docs/architecture.md`, `docs/ledger.md`, `docs/security.md`, `docs/contracts.md`, `docs/mcp.md`, `docs/operations.md` and `docs/design-system.md`. Applied migrations are checksummed: never edit one, add a new migration.
- Branching: `dev` is the default branch and the target for all work and PRs. `main` is the release branch: it changes only by a reviewed merge of `dev`, and a push to `main` publishes the container images and deploys the public site. Never open implementation PRs against `main`.
- Keep PRs focused. Preserve review findings and tests by SHA. Merging: the owner has authorized Claude to merge its own PRs into `dev` (squash merge) once CI is green on the head SHA, the PR has no merge conflict, and every independent review that PR requires (milestone, financial or security, per the PR and the Notion project) is recorded as approved on that same SHA. Never merge with red CI, an unresolved blocking finding or an unreviewed head, and never merge into `main`: the `dev` to `main` release merge, milestone acceptance and public progress claims stay with the owner.
- **Notion follows the repo.** After you change the repository (a PR opened, merged or pushed), update the Notion TallyMed project to record what changed: the PR link, the merged commit, the outcome and the next action, in the matching milestone, task or decision record, and the handoff document when status changed. Do not store status, decisions or plans in the repository.
- Local Claude Code can invoke repository skills. In Projects cloud threads, open and follow the relevant `.claude/skills/<name>/SKILL.md` directly. Use the assigned task details in place of skill arguments.
